# ADR-012: Multi-Instance Configured Inventory for Bitcoin and Electrum

* **Date:** 2026-08-07
* **Decision owners:** SATOSHI//REDLINE maintainers
* **Depends on:**

  * ADR-002 — Capability-Based, Composable Platform Adapters
  * ADR-003 — Separate Observations, Findings, and Diagnoses
  * ADR-006 — Version External API and Report Schemas Independently
* **Scope:**

  * Configured inventory of N Bitcoin nodes and N Electrum backends
  * Component ID policy and `enabled` attention flag
  * Subject-scoped capabilities and finding identity
  * External contract component_id openness
* **Excluded from scope:**

  * Automatic discovery of nodes/backends
  * UI implementation of attention toggles
  * Cross-indexer disagreement correlation rules
  * Legacy singular `bitcoin` / `electrum` config objects

## Context

Installations commonly run more than one protocol surface that Redline must diagnose:

* Bitcoin Core and/or Bitcoin Knots
* Electrs and/or Fulcrum on the same chain

The MVP froze a single `bitcoin.primary` and optional `electrum.primary`. ADR-002 already anticipated multi-instance IDs and subject-scoped capabilities. Product code and contracts did not.

## Decision

1. **Arrays only.** Configuration uses `bitcoin_nodes[]` and `electrum_backends[]`. Singular top-level `bitcoin` / `electrum` objects are rejected.
2. **Operator-owned stable IDs** matching `^[a-z][a-z0-9._-]{1,63}$` (e.g. `bitcoin.knots`, `electrum.fulcrum`).
3. **`enabled` is attention.** `enabled: true` includes the component in inventory and probing; `false` omits it (future UI toggle). Absent install ⇒ not listed.
4. **Subject-scoped capabilities.** Bitcoin RPC, Electrum protocol, and filesystem stat providers are keyed by component ID. Electrum `getblockhash` uses the bound Bitcoin component only.
5. **Finding / diagnosis identity includes component (and edge) scope:**
   * Finding ID: `{scan}-{component}-{code}`
   * Diagnosis ID: `{scan}-{electrum}-{bitcoin}-{code}`
6. **Correlation is edge-driven** over every `uses_chain_from` pair.
7. **Scan rollup** uses `scan.aggregate` for health/coverage; it is not a fake Bitcoin component.
8. **Contracts:** OpenAPI and report schema treat `component_id` as an open string pattern, not a closed four-value enum.

## Consequences

* Lab and example configs list Knots + Electrs + Fulcrum in one scan graph.
* Adding a second Bitcoin node is configuration-only.
* Pre-release singular configs must be rewritten (no compatibility path).

## Status

Accepted.
